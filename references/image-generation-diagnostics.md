# 图像执行差异诊断

仅当已验证输入出现跨环境差异、拒绝或结果退化时读取。它用于查证可见调用条件，不是审核规避或通过率优化方法。

## 官方机制、社区报告与本地观察

2026-09-08核查的公开依据：

- [OpenAI Images 2.0系统卡，Safety stack](https://deploymentsafety.openai.com/chatgpt-images-2-0/automated-evaluations-and-adversarial-testing)明确区分上游拒绝、输入检查与最终图像检查。因此 `moderation_stage: output` 说明该次在输出检查处被阻断，不能单凭它判定原提示词本身违规，也不能判断未返回图像是否真的存在违规内容或误判。
- [OpenAI图像工具指南，Revised prompt与Multi-turn editing](https://developers.openai.com/api/docs/guides/tools-image-generation)说明 Responses 图像工具存在主模型改写提示词、返回 `revised_prompt`、引用上一响应/图像的机制。这证明需要区分用户原文与实际下游输入；不证明某次 ChatGPT 或 Codex 内置调用采用了相同机制/状态。
- [开发者社区2026-08个案](https://community.openai.com/t/api-issue-moderation-over-refusals-on-gpt-image-2-with-moderation-low-where-chatgpt-always-succeeds/1388964)报告了GPT Image 2 API输出拦截与ChatGPT成功并存。它支持“其他用户也观察到此现象”，没有给出获官方确认的根因或稳定解决方法。

本案例的判断：

| 假设 | 当前证据 | 可作结论 |
| --- | --- | --- |
| 本次改写造成差异 | 两个改写版和一次原文均在当前工具中被输出拦截 | 改写是干扰变量，但不能解释全部现象；先前改写失败不能代表原文失败 |
| 随机候选图导致不同裁定 | 输出审核会检查候选结果；没有固定seed或足够同条件样本 | 合理但未证实，不能算通过率，也不将重复抽样当作解法 |
| 对话/旧图上下文影响 | 官方存在多轮和自动改写机制；本地三次没有显式传历史图 | 不能断言当前内置服务没有内部状态，也不能断言上下文已污染；其影响未被隔离验证 |
| 产品面/版本/默认参数不同 | 社区有同类跨产品报告；本地工具不暴露模型快照、内部改写、seed或审核控制 | 不能把某API参数或“更宽泛”假设当作本工具能力；不能确定阈值或配置差异 |

诊断只保存必要信息：原文与实际送出文本的哈希/差异、产品面和时间、已知模型/参数、显式参考图数量及哈希、是否编辑/带先前响应、完整错误的阶段/类别与请求标识。未暴露字段填“未知”；不读取无关账户、凭据或私有系统指令。支持工单可使用已有请求标识和最小复现，发送须有用户授权。

当前未找到并验证可在本工具稳定解决该输出拦截的办法。修正的是提示保真、改写边界和诊断方法；不要将它宣传为放宽生成范围或绕过审核的能力。


## 新增的协调任务证据

本任务随后核验了DIR任务保存的原生工具成功图：同一用户原文、加一张身份参考，产出五视图和深V；同任务扩写版有同一参考但失败。我们的原文调用没有显式图像输入。原文文字可对齐，整组输入和任务上下文不相同；不能从单例排除采样、输入差异或内部状态。可保留此成功组合用于正常任务的保真复用，但不宣称它解决了审核根因或能保证重复成功。

证据见 [本地验证记录](../tests/forward-evidence/female-garment-expression-review.json)。原始会话文本、参考图和结果像素均不随Skill分发。

协调任务随后补测了3512字符的“原文＋正式引用/角色契约”，同一身份参考下仍被输出拦截。三种条件各一次：扩写失败、原文成功、原文加契约失败。必要的引用预检可以独立于模型提示正文保存；若确需补入正文，应标为变体。不能据此推出任意契约、某种语言或某个长度必然影响通过，也不能将正式准备成功称为正式人物出图成功。
