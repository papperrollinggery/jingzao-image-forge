# 参考蒸馏：先看全，再选择，再投影

用于用户说“蒸馏这组图”“保持这种人物感觉”“动作、表情、发色也要像参考”或从已观察视频提炼单帧控制。普通无参考 create 不需要这份表。

镜造有两种不同交付：**风格胶囊**保存跨题材的材质、光色与摄影机制；**reference profile**保存本次需要保留的具体视觉特征。不要把“不复制人物身份”扩大成不保留发色、表情、姿态或身材。用户要求的是完整视觉处理时，先做 profile，再视需要提炼更抽象的 capsule；两者不混作同一个输出。

## 观察与选择

先实际查看每张原图，逐图建立 [reference-profile.json](../templates/reference-profile.json)。一组图有不同发色、姿势或背景，就保留分支，不取平均。仅在本次蒸馏中逐项检查14项；不可见或不适用是有效结论，不靠编造填表。

| 项 | 写成可见关系 | 避免丢失或混淆 |
|---|---|---|
| face_design | 用户明确的面部设计方向、成年目标及来源身份边界 | 东亚设计若是用户要求必须进入目标；不根据像素断言真实族裔或年龄，不默认复制身份 |
| hair | 颜色、长度、刘海、分缝、发束走向与遮眼关系 | “精细发丝”不能替代“浅铂金齐刘海短发” |
| makeup | 眼周、睫毛、唇色及妆面反差 | 不只写“漂亮妆容” |
| expression | 眉眼松紧、唇开合、下颌、可见情绪 | 不把微分唇、疏离或疲惫统一改成微笑 |
| gaze | 看向哪里、眼睛是否被遮挡 | 对镜头、低垂、侧看不能互换 |
| pose | 头部倾角、肩胯旋转、躯干俯仰、承重 | 站、坐、倚靠和前倾分别记录 |
| action | 哪只手/哪侧画面、接触点、正在做什么 | 单帧只证明可见状态，不把托杯变举手，不从一帧编完整动作 |
| body | 可见胸腰胯、肩背、四肢体量与遮挡 | 连同[身材表单](body-profile.md)；服装外形不是身体，近景不补全身 |
| wardrobe | 轮廓、颜色、关键构造、开口/覆盖、承托与材质 | 不能为了抽象风格删掉用户要求的服装；未知衣片明确为新设计 |
| camera | 画幅、景别、视角、裁切、透视和景深 | 焦距可作为目标选择，不伪称来源实测 |
| lighting | 光向、光源大小、脸部补光、背景层级 | 不把窗侧光与棚拍混在一张图 |
| palette | 谁承担哪种颜色，肤色如何独立 | 保留色彩归属，不用滤镜统一染色 |
| surface | 肤面反差、发丝、织物、光学软化各自职责 | 不让皮肤磨平或把低反差误成模糊 |
| environment | 必要场景关系、道具、背景类型 | 不自行编职业、花园、卧室或叙事事件 |

每项记录 `source_ids`、`evidence`、`observation`、`decision`、`prompt`、`reason` 和 `review_check`。

- `preserve`：保留观察到的当前特征，`prompt` 写一条完整正向视觉描述。
- `adapt`：按目标改变已观察部分，必须写 `reason`。来源未知的背面或体型若由用户另行设定，写进 base spec 的现有字段，不从 `unknown` facet 投影。
- `omit`：本次不采用，必须说明原因。用户明确要求的项不能未经说明静默删掉。
- `unknown`：证据不足；不向生成正文补写该属性，说明未知原因。
- `not_applicable`：非人物图不套人物事实。对其不适用项作标记即可。

`observed`/`partial` 必须绑定真实观察的 source ID；来源年龄/身份/隐藏身体不能凭看图确定。若来源只见颈与手腕，body 可保留这两个可见范围，并在 observation 明确其余未知；这不是胸腰胯测试。

## 编译和附图

把用户当前意图放在 target spec。将14项里的选中描述写在 profile，每项只承担一件可见决策。先人工核对其与 target spec 的身份、服装、配色和改动要求一致；程序不会理解语义矛盾，也不会自动覆盖已有字段。冲突在源文件解决，不能靠把同一矛盾同时送给模型。

```bash
python3 scripts/compile_prompt.py tests/forward-specs/reference-profile-cream-rose.json \
  --reference-profile examples/reference-profile-cream-rose.json --platform openai
```

公开例子中的图片来源为 `runtime:cream-rose-reference` 占位：生成前绑定实际参考文件，再按 `imagegen_call_plan` 传给工具。不要把这个占位示例当成已经附图或可直接生成的收据。

`--reference-profile` 与 `--style-capsule` 互斥。profile 是已经选定单帧特征的投影，不能再无判断地叠加通用胶囊的分支和禁项；需要胶囊质感时先把适用部分写进 profile 的材质、光色等项。旧 `--style-capsule` 与所有已有 spec 接口继续可用。

程序只把选中的 `prompt` 追加到现有 `scene.summary`；不会改掉原 spec、自动重写人物或发明新 schema 字段。只去除完整重复条款，绝不靠子串或词数截断删掉设计要求。`reference_profile_audit` 单独回传每项投影结果与视觉检查点，观察和审核元数据不进模型正文。

- `attached`：所有声明 source ID 必须对应 target spec 的 `must_attach: true` 图片；真实路径、引用窗口和工具能力仍由既有 reference delivery 检查。
- `text_transfer`：仅用于明确的脱离原图迁移试验；它不能证明实际附图或源图相似度。若用户要求参考图生成，不能为方便擅自切到此模式。
- 一张图能完成当前视觉任务时只附必要图。多图先分角色，不让附件数决定成图必须包含什么。

## 从 DIR 接入的方法与可选联动

2026-09-08检查到 DIR 的实际方法分工为：`video-evidence-workbench` 提供镜头/帧与声音证据，`film-breakdown-distiller` 提炼“观察 → 机制 → controls → 误用边界 → review check”，DIR 组织“参考效果 → 目标需要 → 实际缺口 → 一个修正 → 回看”。镜造将这套方法落实到本页及可执行 profile 投影，保留自己作为单帧编译器的职责。

处理视频时：如本机有 Workbench，读取其 Skill 并复用同一项目已有效的镜头证据。图像 profile 的 source IDs 可采用已观察帧的稳定 ID；在项目内保留帧来源/时间与哈希，不把单帧动作推成视频时间序列。需要电影机制解释时按需调用 `film-breakdown-distiller`，不要重新抄一套下载器、路由器或编排器。静态图片直接视觉观察即可，不为本来不需要的视频流程制造依赖。

这些子 Skill 是可选深化，不是镜造安装前提；单独安装镜造仍可完成静态参考观察、14项选择、投影、附图预检和逐项验收。上游 DIR 目前未增加 `--reference-profile` 标准传递字段；联动时先用 `scripts/reference_profile.py PROFILE --spec SPEC` 取得展开后的标准 spec，再交给 DIR 已支持的标准 spec 路径。不要宣称已修改或实测上游 DIR 执行器。

## 验收与返工

先确认当前传入的文字与图片，再检查真实返回图。逐项读取 `review_check`，标记 matched / partial / missed / untestable，并保留具体画面依据。发色、表情、手位、身材、服装任一关键项失败，就不能只凭色彩相似判整体通过。

只修改真实失败项，复用未变且仍有效的观察。若手势或遮挡文字难以控制，使用原参考或更清晰的相应区域/姿态参考；不靠重复“必须”增重。不因一张近景成功就宣称全身或视频连续性通过。

提示正文修正为清晰、无歧义的当前视觉意图，不能承诺解决生成服务拦截。发生拒绝后保留阶段/错误与整组输入，读[执行差异诊断](image-generation-diagnostics.md)。重新定义穿着、姿态或场景的对照须标明设计变化；禁止把删除用户要的特征、换词绕过或未返回图像记成改进成果。
